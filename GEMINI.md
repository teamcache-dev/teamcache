# TeamCache

Shared AI context cache for software teams. Reduces cold start by sharing file summaries (static and AI-generated) across the team via git.

## Project Overview

- **Purpose:** Eliminate token-heavy "cold starts" for AI tools by providing pre-computed structural and descriptive context.
- **Main Technologies:**
    - **Language:** Python 3.10+
    - **CLI:** [Click](https://click.palletsprojects.com/)
    - **Server:** [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) via `mcp` Python SDK.
    - **Parsing:** [Tree-sitter](https://tree-sitter.github.io/) for AST-level symbol extraction (supports 11+ languages).
    - **Storage:** Content-addressed immutable JSON objects in `.teamcache/objects/` (git-committed) and a local SQLite index in `.teamcache/local/index.sqlite` (gitignored).
    - **Search:** FTS5 for keyword search, optional `sentence-transformers` for semantic search.

## Architecture & Core Concepts

- **Cache Keys:** `sha256(sha256(file_bytes) + "|" + schema_version)`. File changes automatically result in new keys, ignoring old objects.
- **Two-Tier Summaries:**
    - `static`: Structural snapshots (symbols, imports) generated by `teamcache index`.
    - `ai`: Richer summaries written by AI tools via `cache_summary()` MCP tool. `ai` summaries take precedence.
- **Data Flow:**
    - `teamcache index` walks the repo, parses files, and writes objects.
    - `teamcache sync` rebuilds the local SQLite index from committed objects.
    - `teamcache serve` starts an MCP stdio server that AI tools use to get context and store summaries.

## Building and Running

### Development Setup

```bash
# Install with all extras (symbols + embeddings) and dev dependencies
pip install -e ".[all,dev]"

# Run tests
pytest

# Run tests with coverage
pytest --cov=teamcache
```

### Common Commands

| Command | Purpose |
|---|---|
| `teamcache init` | Initialize `.teamcache` directory and git hooks. |
| `teamcache index` | Generate static summaries and rebuild local DB. |
| `teamcache sync` | Sync local DB with committed objects (run after `git pull`). |
| `teamcache serve` | Start the MCP server. |
| `teamcache doctor` | Check health of the installation and database. |

## Development Conventions

### Coding Standards

- **Object Access:** Always use `ObjectStore` protocol (in `store.py`) for reading/writing summary and symbol objects. Do not call low-level file write functions directly.
- **Database Migrations:** `db.py` migrations are append-only. Add new migrations to the end of the `MIGRATIONS` list; never renumber existing ones.
- **Connection Management:** `mcp_server.py` uses a split connection strategy: `read_conn` for SELECTs, `write_conn` for INSERTs/UPDATEs to avoid lock contention in WAL mode.
- **Quality Scores:** `quality_score` is computed on-the-fly during DB writes based on word count and specificity. It is not stored in the JSON object files.
- **Secret Protection:** `secrets.py` contains regex patterns to block summaries containing credentials/secrets before they are written to disk.

### Testing Practices

- Use `pytest` with `tmp_path` and `monkeypatch` fixtures.
- **CLI Testing:** Use `click.testing.CliRunner`.
- **Subprocess Mocking:** Patch `subprocess.run` and `shutil.which` at the module level where they are imported (e.g., `teamcache.cli.subprocess`).
- **Tree-sitter Testing:** Skip tests if required parsers are missing (`pytest.skip`).
- **Isolation:** Never write to the real repo root or user home directory during tests.

## Key Modules

- `teamcache/cli.py`: CLI command definitions and agent installation logic.
- `teamcache/mcp_server.py`: FastMCP server and tool implementations.
- `teamcache/db.py`: SQLite schema, FTS5 queries, and migrations.
- `teamcache/symbols.py`: Tree-sitter integration for AST symbol extraction.
- `teamcache/files.py`: Repository file iteration and static summary generation.
- `teamcache/store.py`: Abstraction for content-addressed storage.
